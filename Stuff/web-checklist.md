# Веб-чеклист

Минимум, что прохожу по любой новой точке. Не «золотой стандарт», а то, что реально выдавало находки.

## Разведка

- [ ] Стек: заголовки (`Server`, `X-Powered-By`), куки (PHPSESSID, JSESSIONID, connect.sid), favicon-хэш
- [ ] robots.txt, sitemap.xml, .git/HEAD, .env, backup-файлы (~, .bak, .old)
- [ ] Перебор каталогов: dirsearch с дефолтным словарём + `api/`, `v1/`, `v2/`, `admin/`, `dev/`, `staging/`
- [ ] Wappalyzer / whatweb — справочно, заголовки врут

## Точки входа

- [ ] Каждый параметр GET/POST: что отражается, что меняет поведение
- [ ] Скрытые поля, куки, заголовки (X-Forwarded-For, User-Agent, Referer)
- [ ] Методы PUT, DELETE, PATCH — иногда факапят в авторизации
- [ ] API: swagger/openapi, разные права между эндпоинтами, массовое присвоение (role прямо в JSON)

## Авторизация

- [ ] IDOR: менять id на чужой, в том числе закодированные (base64, hashids)
- [ ] Залогиненный юзер дёргает админские роуты
- [ ] Сброс пароля: предсказуемый токен, отражение в ответе, подмена почты в запросе

## Инъекции — по обстановке

- [ ] SQLi: кавычка в каждый параметр, ошибки смотреть в Burp, не в рендере
- [ ] SSTI: `{{7*7}}` туда, где отражают
- [ ] XSS: отражённый везде, хранимый в комментах / профиле / имёнах
- [ ] SSRF: URL-параметры, вебхуки (requestbin / interactsh), `127.0.0.1` + перебор портов
- [ ] LFI: path-параметры, обход `../` через `..;/`, `%2e`, `....//`
- [ ] Command injection: `; | & $( )` в параметрах, проверка через задержку `ping -c 5`

## Бизнес-логика

- [ ] Отрицательные числа в ценах и количествах
- [ ] Повторная отправка форм (race), дабл-списание / начисление
- [ ] Границы: 0, -1, максимум int, пустая строка, null
- [ ] Многошаговые флоу: пропуск шага (оплата → подтверждение)
