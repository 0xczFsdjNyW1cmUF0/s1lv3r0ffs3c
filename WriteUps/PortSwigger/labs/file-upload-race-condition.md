# Веб-шелл через race condition: окно между записью и удалением

**Лаба:** [Web shell upload via race condition](https://portswigger.net/web-security/file-upload/lab-file-upload-web-shell-upload-via-race-condition) (Expert, File upload)
**Суть:** загруженный файл проверяется после записи на диск. До удаления он ненадолго доступен в веб-каталоге, и за это время PHP-скрипт можно выполнить.

## Диагностика

Проверенные обходы (Content-Type, null byte, polyglot, .htaccess) не сработали. Ответ на загрузку приходит примерно через секунду. Задержка даёт повод проверить гонку, но сама по себе не доказывает, что файл уже записан. В этой лабе файл доступен между записью и удалением после неудачной проверки.

## Эксплуатация

Порядок обработки на сервере:

```
1. принять файл
2. записать в /files/avatars/
3. проверить тип
4. удалить, если не картинка
```

Между шагами 2 и 4 файл доступен для запроса. Ниже — неполный фрагмент для Turbo Intruder: `get_req` в нём не определён, а HTTP/2-движок для single-packet attack явно не выбран. Он сохранён из заметки к шаблону `race-single-packet-attack`, но не является готовым скриптом.

```python
def queueRequests(target, wordlists):
    engine = RequestEngine(endpoint=target.endpoint, concurrentConnections=10)
    engine.queue(target.req, gate='race1')          # POST /my-account/avatar с exploit.php
    for x in range(5):
        engine.queue(get_req, gate='race1')          # GET /files/avatars/exploit.php?cmd=cat /home/carlos/secret
    engine.openGate('race1')
    engine.complete(timeout=60)
```

Один POST загружает шелл, а пять GET-запросов пытаются его выполнить. Часть GET-запросов получает 200 с содержимым `/home/carlos/secret`: удалось попасть в окно между записью и удалением.

## Как обнаружить

Выполнение PHP из каталога аватаров — подозрительное событие. Стоит сопоставлять запросы к загруженным файлам с журналами их создания и удаления. На Linux для наблюдения за файловыми операциями можно использовать auditd; события нужно сохранять независимо от удаления самого файла.

## Заметка

Задержка ответа — повод проверить, не становится ли файл доступен до завершения проверок. Синхронизация запросов уменьшает влияние сетевых задержек, но не гарантирует попадания в окно. Само название шаблона ещё не означает, что конкретный скрипт использует single-packet attack.
