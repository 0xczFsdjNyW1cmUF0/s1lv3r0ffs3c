# 2FA-байпас брутфорсом: макрос против logout-защиты

**Лаба:** [2FA bypass using a brute-force attack](https://portswigger.net/web-security/authentication/multi-factor/lab-2fa-bypass-using-a-brute-force-attack) (Expert, Authentication)
**Суть:** четырёхзначный код без rate limit — космос для перебора. Защита — логаут после двух неверных попыток, и она же ломается автологином через макрос.

## Проблема

Креды carlos:montoya есть, код из 4 цифр — 10 000 вариантов, перебирается за минуты. Но после двух неверных кодов сессия умирает, и перебор обрывается на старте.

## Решение: session handling rule + macro

Идея — перед каждым запросом Intruder'а автоматически логиниться заново. Burp умеет:

1. **Sessions → Session handling rules → Add**, скоуп — все URL.
2. **Rule Action → Run a macro**, записываем макрос из трёх запросов:
   ```
   GET  /login
   POST /login          (carlos:montoya)
   GET  /login2
   ```
3. Test macro — последний ответ должен быть страницей с запросом кода. Значит, перед каждым запросом Intruder'а Burp молча восстанавливает живую сессию, и защита «два неверных — логаут» никогда не накапливает счётчик.

## Перебор

`POST /login2` в Intruder, позиция на `mfa-code`, Numbers 0–9999, step 1, min/max digits 4 (чтобы `0007`, а не `7`). **Resource pool: maximum concurrent requests = 1** — иначе параллельные гада перепутаются со свежими сессиями из макроса. Однажды прилетает 302 — код принят, «Show response in browser», сессия carlos наша.

## Заметка

Полезно для BSCP: это не «взлом 2FA», это «защита, которая наказывает атакующего логаутом, но не ограничивает скорость». Как только сессию можно восстанавливать автоматически, логаут превращается из стены в мелкое неудобство. Настоящий фикс — rate limiting и код побольше четырёх цифр.
