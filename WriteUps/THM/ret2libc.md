# ret2libc: первая ROP-цепочка, которая собралась

**Машина:** [ret2libc](https://tryhackme.com/room/ret2libc) (medium, pwn, Linux)
**Инструменты:** gdb + gef (или pwntools), Ghidra, checksec.

## Разбор бинаря

`exploit_me` спрашивает имя и печатает его. 30 символов `A` — segfault, переполнение есть. checksec:

- NX — включён (шеллкод на стеке не исполнится)
- canary — нет
- RELRO — partial
- в коде есть `setuid(0)`

NX не даст исполнить код на стеке, но можно перезаписать return address и собрать ROP-цепочку с вызовом функций уже загруженной libc. Ghidra показывает виновника: `gets()` в буфер на 10 байт, без всякой проверки длины.

## Оффсет

В gdb через gef:

```
pattern create 100
run   # вставляем паттерн
pattern search $rsp
```

Получаем смещение до сохранённого адреса возврата. В pwntools для этого есть `cyclic` и `cyclic_find`.

## Цепочка

Идея ret2libc: в libc лежит всё нужное, включая строку `/bin/sh`. Собираем из гаджетов программы:

```
[padding до return address]
[pop rdi; ret]      ← гаджет, кладёт аргумент в rdi
[адрес "/bin/sh"]
[адрес system]      ← вызов system("/bin/sh")
```

`pop rdi; ret` ищется `ROPgadget`-ом или `ropper`-ом по бинарю. Адреса `system` и строки `/bin/sh` в libc берутся из отладки (gdb: `p system`, `search-pattern /bin/sh`). Бинарь вызывает `setuid(0)` до чтения ввода — при успешном вызове и наличии нужных прав шелл из `system()` запускается от root.

Оформляется всё скриптом на pwntools: `padding + p64(pop_rdi) + p64(binsh) + p64(system)` — запуск, шелл, флаг.

## Заметка

NX запрещает выполнение кода со стека, но не мешает перезаписать адрес возврата и использовать существующий код. Для воспроизводимой цепочки ещё нужно учитывать ASLR, PIE и выравнивание стека; в записи эти условия не разобраны.
