# 0day: Shellshock и kernel 3.13

**Машина:** [0day](https://tryhackme.com/room/0day) (medium, Linux)
**Цепочка:** nikto → Shellshock в CGI → шелл → overlayfs → root.

## Футхолд

Открыты 22 и 80. Подсказка комнаты честная: «hidden directories are a rabbit hole». Гобустер пускать можно, но толку нет. nikto сразу показывает уязвимость к Shellshock на `/cgi-bin/test.cgi`.

Эксплуатация — одной строкой, без метасплойта:

```bash
curl -A "() { :; }; echo Content-Type: text/html; echo; /bin/bash -c 'id'" http://0day.thm/cgi-bin/test.cgi
```

Bash исполняет команды после определения функции из переменной окружения (User-Agent прокидывается в окружение CGI-скрипта). Дальше меняем команду на реверс-шелл.

## Привилегии

ОС — Ubuntu 14.04.1, ядро 3.13.0. Здесь для повышения привилегий используется overlayfs local privesc (37292): переносим исходник на машину и компилируем.

Первая попытка сборки падает: `gcc` не находит `cc1`. В этом окружении помогает исправление PATH:

```bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

Дальше компиляция и запуск проходят, root.

## Как обнаружить

Если формат access log включает User-Agent, в нём можно искать `() { :; };`. Это признак данного payload, а не универсальная сигнатура Shellshock. На сервере стоит проверять запуск `/bin/bash` из CGI-скрипта: auditd может записать execve, если настроены соответствующие правила. Локальный эксплойт ядра не обязан оставлять сетевые следы; для его поиска нужны события процессов, файлов и другие данные с хоста.

## Заметка

Здесь уязвимы и Bash, и ядро. Эксплойт ядра зависит от версии и сборки системы и может вызвать сбой. Перед запуском стоит проверить исходник и условия применимости.
