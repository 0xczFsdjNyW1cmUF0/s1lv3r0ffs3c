# LocalPotato: своп NTLM-контекстов + DLL-хиджacking

**Машина:** [LocalPotato](https://tryhackme.com/room/localpotato) (medium, Windows, CVE-2023-21746)
**Суть:** LPE через флaw в локальной NTLM-аутентификации → запись любых файлов от SYSTEM → добиваемся исполнения через StorSvc.

## Вектор 1: LocalPotato

Брешь в NTLM local authentication. Атака идёт в три движения:

1. Поднимаем rogue-сервер и заставляем привилегированный процесс аутентифицироваться к нему — Security Context A создаётся, но не отдаётся сразу.
2. Параллельно наш unprivileged-клиент коннектится к локальному SMB-серверу — создаётся Context B.
3. Подменяем ID контекстов: привилегированный процесс получает контекст нашей SMB-сессии. Его SYSTEM ассоциируется с нашим подключением.

Итог: наш юзер получает доступ к любой шаре — включая `C$` и `ADMIN$` — с правами SYSTEM. Можем писать и читать файлы где угодно. Но исполнить код это само по себе не даёт.

## Вектор 2: StorSvc → исполнение

Тут добирает BlackArrowSec: у сервиса StorSvc есть публичный RPC-метод `SvcRebootToFlashingMode`, который провоцирует загрузку отсутствующей `SprintCSP.dll` — её ищут по PATH, и низкопривилегированный юзер в PATH не пишет. А LocalPotato пишет куда угодно.

Цепочка: msfvenom делает вредоносный `SprintCSP.dll` → LocalPotato закидывает его в `system32` → RPC-вызов к StorSvc → DLL подгружается от SYSTEM → шелл.

```bash
# триггер RPC (одна из реализаций — через специальный бинарник с https://github.com/blackarrowsec/redswagger)
StorSvc.exe 127.0.0.1   # или аналогичный клиент SvcRebootToFlashingMode
```

## Заметка

LocalPotato открывает файл, но не исполняет код — это важное разделение. Сам по себе arbitrary file write половина привилегий; вторая половина — всегда поиск чего-то, что грузит DLL (сервис, PATH-hijack). Два отдельных вектора, склеенных в один рабочий LPE.
