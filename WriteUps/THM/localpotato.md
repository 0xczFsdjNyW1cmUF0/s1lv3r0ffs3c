# LocalPotato: подмена NTLM-контекстов + DLL hijacking

**Машина:** [LocalPotato](https://tryhackme.com/room/localpotato) (medium, Windows, CVE-2023-21746)
**Суть:** LPE через ошибку в локальной NTLM-аутентификации → запись любых файлов от SYSTEM → добиваемся исполнения через StorSvc.

## Вектор 1: LocalPotato

Ошибка в локальной NTLM-аутентификации. Схема атаки:

1. Поднимаем rogue-сервер и заставляем привилегированный процесс аутентифицироваться к нему — Security Context A создаётся, но не отдаётся сразу.
2. Параллельно наш unprivileged-клиент коннектится к локальному SMB-серверу — создаётся Context B.
3. Подменяем ID контекстов: привилегированный процесс получает контекст нашей SMB-сессии. Его SYSTEM ассоциируется с нашим подключением.

Итог: наш юзер получает доступ к любой шаре — включая `C$` и `ADMIN$` — с правами SYSTEM. Можем писать и читать файлы где угодно. Но исполнить код это само по себе не даёт.

## Вектор 2: StorSvc → исполнение

Для выполнения кода используется техника BlackArrowSec: у сервиса StorSvc есть публичный RPC-метод `SvcRebootToFlashingMode`, который провоцирует загрузку отсутствующей `SprintCSP.dll` — её ищут по PATH, и низкопривилегированный юзер в PATH не пишет. А LocalPotato пишет куда угодно.

Цепочка: msfvenom делает вредоносный `SprintCSP.dll` → LocalPotato закидывает его в `system32` → RPC-вызов к StorSvc → DLL подгружается от SYSTEM → шелл.

```bash
# триггер RPC (одна из реализаций — через специальный бинарник с https://github.com/blackarrowsec/redswagger)
StorSvc.exe 127.0.0.1   # или аналогичный клиент SvcRebootToFlashingMode
```

## Как обнаружить

Локальная NTLM-аутентификация и обращения к SMB сами по себе не доказывают LocalPotato. Полезнее сопоставлять их с появлением DLL в `system32`: запись можно увидеть в Sysmon EID 11 при соответствующей конфигурации. Загрузку DLL также стоит отслеживать, например через Sysmon EID 7; это отдельный этап цепочки.

## Заметка

LocalPotato даёт привилегированный доступ к файлам, но не запускает код сам по себе. В этой цепочке запись DLL превращается в выполнение через StorSvc. Загрузка DLL — один из способов использовать arbitrary file write, а не обязательное продолжение любой такой атаки.
