# FAT32 Analysis: форензика файловой системы с нуля

**Машина:** [FAT32 Analysis](https://tryhackme.com/room/fat32analysis) (hard, DFIR)
**Инструменты:** HxD, Autopsy 4.21. Всё на Windows-лаборатории, образы в `C:\FAT32_analysis\`.

## Зачем вообще FAT32

Нет прав доступа — любой может трогать любой файл. Нет журналирования. Флешки и IoT-девайсы форматируют в FAT32 массово, поэтому атакующие его любят. Разбор идёт по картинке диска в HxD.

## Структура, которую надо знать наизусть

```
Reserved Area → FAT Area (FAT1 + FAT2) → Data Area
```

Boot sector (сигнатура `55 AA` в конце) отдаёт метаданные тома: bytes per sector, sectors per cluster, сколько reserved-секторов, сколько FAT-таблиц, размер каждой. От этих чисел считаются все оффсеты — без них никуда. Порядок little endian, с этим спотыкаешься раз пять, пока не привыкнешь.

## Что искал руками

- **Скрытые файлы.** Байт атрибутов SFN-записи на оффсете `0x0B`: `0x02` — hidden. Ставится и снимается кем угодно, permissions не проверяются.
- **Удалённые файлы.** При удалении содержимое не стирается — первый байт имени меняется на `0xE5`. Контент лежит в кластерах до перезаписи. Восстановление = найти E5-запись, вытащить кластерную цепочку из FAT.
- **Таймстомпинг.** FAT хранит три метки: создание, изменение, последний доступ. Логика простая: created позже modified — невозможно, accessed раньше modified — невозможно. Autopsy удобно рисует таймлайн, аномалия видна сразу.
- **Слэк-спейс и карвинг.** Хвост кластера не обнуляется — данные «хвоста» прошлых файлов читаются. Дёргал base64-строки из восстановленных скриптов и декодил отдельно.

## Заметка

После этой комнаты читаешь hex-дамп не как шум, а как оглавление. Главное, что осталось: в FAT32 удаление — это смена одного байта, и всё «удалённое» лежит на блюдечке, пока его не перезапишут.
