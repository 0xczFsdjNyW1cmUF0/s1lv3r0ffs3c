# NoScope: Finding RCE — обход песочницы через `returnClass`

**Машина:** [NoScope: Finding RCE](https://tryhackme.com/room/noscoperce) (medium, web, CVE-2026-35482)
**Платформа:** Alf.io (Java/Spring Boot), админка `/admin`, креды выданы в задании.

## Уязвимость

Alf.io позволяет админу писать JS-расширения на события платформы. Исполняются они в песочнице Mozilla Rhino + валидация скрипта по deny-листу: режутся `java.lang.Runtime`, ключевые слова рефлексии и т.п.

Песочница помещает в scope объект `returnClass` (нужен движку для десериализации возврата). Через него доступен статический метод `forName(String)` класса `java.lang.Class`. А класс, спрятанный в строковом литерале, deny-лист не видит:

```javascript
var rt = returnClass.forName('java.lang.Runtime');
var s  = returnClass.forName('java.String');
var r  = rt.getMethod('getRuntime').invoke(null);
rt.getMethod('exec', s).invoke(r, 'id');
```

В примере выше есть ошибка имени класса: `java.String` не является стандартным классом Java. Фрагмент оставлен как в исходной заметке и требует исправления и проверки в среде лабораторной.

Фильтрация текста скрипта не заменяет ограничения на доступные Java-объекты и вызовы.

## Доставка

Всё по HTTP через админ API:

1. GET на `/admin/api/*` — сеет куки `XSRF-TOKEN` и сессию.
2. POST `/authenticate` с логином/паролем и заголовком `X-CSRF-TOKEN` — 302 = вошли.
3. POST `/admin/api/extensions` ровно с телом `{path, name, enabled, script}`. Лишнее поле — 404, протухший токен — 403.
4. `path: "-"` (global scope), подписка на `EVENT_STATUS_CHANGE`. Меняем статус события — скрипт стреляет.

## Эксфильтрация через лог

Реверс-шелл не открылся, wget тоже не смог подключиться наружу. Это согласуется с фильтрацией исходящих соединений, но само по себе её не доказывает. Другой канал — лог выполнения расширения. Если расширение бросает исключение, Alf.io пишет значение в лог выполнения, а `GET /admin/api/extensions/log` его отдаёт. Значит, payload читает `flag.txt` и `throw`-ит содержимое — содержимое можно прочитать через тот же API.

## Как обнаружить

Обход текстового фильтра не обязательно оставляет отдельное событие. Для наблюдения за вызовами `Class.forName` внутри движка нужна дополнительная инструментализация Java; стандартного аудита для этого недостаточно. Также стоит проверять изменения расширений через `/admin/api/extensions` и содержимое логов выполнения. Запись скрипта, его запуск и чтение лога — разные точки наблюдения.

## Заметка

Здесь доступ к Java-классам позволяет обойти текстовый фильтр. Для получения результата команды обратное соединение не обязательно: приложение уже отдаёт лог выполнения расширения.
