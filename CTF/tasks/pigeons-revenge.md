# PigeonsRevenge: port knocking, бэкдор Webmin и инъекция команд

**Таск:** PigeonsRevenge (aclabs.pro, сезон 5, web/linux, 3 флага)
**Источник:** [разбор seobuster на Хабре](https://habr.com/ru/articles/1024360). Ниже — конспект этого прохождения.
**Цепочка:** метаданные видео → port knocking → бэкдор Webmin → root в контейнере → ligolo → SSH → SETENV и инъекция команд через переменную окружения → root на хосте.

## Разведка

Открыт только порт 80, веб-сервер — nginx. На сайте есть видео и «план мести». Перебор каталогов ничего не даёт. В метаданных видео exiftool находит последовательность портов для port knocking: 2, 8, 10.

```bash
sudo nmap -Pn -p 2,8,10 <ip>
sudo nmap -Pn -sV <ip>   # после стука открылся 10000 — Webmin 1.910
```

## Root в контейнере

В Webmin 1.910 присутствует бэкдор в `password_change.cgi` (CVE-2019-15107), доступный без аутентификации. Автор использует модуль Metasploit `linux/http/webmin_backdoor` с `set ssl true` и получает обратную оболочку с uid=0. Это root внутри контейнера и только первый флаг.

## Пивотинг

В `/root/.bash_history` остаётся попытка `ssh sparrow@172.18.0.1`. Через ligolo-ng автор получает доступ к сети Docker и подключается по SSH под sparrow с паролем из сюжета задачи. Следующий флаг находится в домашнем каталоге sparrow.

## SETENV и инъекция команд

В `sudo -l` есть правило `(root) SETENV: NOPASSWD: /usr/bin/pigeon_root --crumbs /root/root`. SETENV разрешает передать переменную окружения привилегированному процессу. Анализ в Ghidra показывает, что бинарник читает `PIGEON_SEEDS`, удаляет некоторые специальные символы и пробелы, затем передаёт результат в `system()`. Табуляция фильтром не удаляется:

```bash
sudo PIGEON_SEEDS=$'cat\t/root/root' /usr/bin/pigeon_root --crumbs /root/root
```

Так читается финальный флаг. В исходном разборе тем же способом запускается скрипт обратной оболочки с правами root.

## Как обнаружить

Нужно отслеживать изменения sudoers и проверять, какие переменные может получить разрешённая команда. SETENV сам по себе не означает выполнение произвольного кода: здесь проблема в том, что программа передаёт содержимое переменной в `system()` после неполной фильтрации. Port knocking можно искать в сетевой телеметрии или журналах межсетевого экрана, если нужные пакеты записываются.

## Заметка

Подсказка к port knocking лежит в метаданных видео, а не в скрытом каталоге. В последнем шаге важно сочетание двух условий: передача переменной через sudo и небезопасное использование этой переменной программой. Удаление пробелов не устраняет инъекцию команд.
